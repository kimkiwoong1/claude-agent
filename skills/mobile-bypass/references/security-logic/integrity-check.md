# 무결성/서명 검증 우회

## 구현 패턴별 식별

| grep로 나온 것 | 탐지 방식 | 우회 접근 |
|---|---|---|
| `PackageManager.GET_SIGNATURES`, `signingInfo`, `checkSignature` | 앱 서명 해시 하드코딩 비교 (리패키징/변조 탐지) | 해당 비교 메서드 훅해서 항상 true 리턴, 혹은 원본 서명 해시값 자체를 원본 APK 그대로 사용 |
| APK 자체 체크섬/해시 자체검증 (`classes.dex` 해시 등) | 파일 변조 탐지 | 해시 비교 함수 훅, 원본 그대로 쓰면 애초에 문제 안 됨(테스트 목적상 원본 APK 유지가 우선) |
| Debuggable 플래그 체크 (`ApplicationInfo.FLAG_DEBUGGABLE`) | 디버그 빌드 탐지 | `ApplicationInfo` 필드 훅 |
| 커스텀 무결성 SDK (상용 앱쉴드/난독화 솔루션 - 예: 잉카인터넷 nProtect, INKA Entrust 등) | 다층 방어, 자체 프로세스 감시 | 벤더별 시그니처 다름, 우선 `security-logic/anti-frida.md`의 anti-ptrace 우회부터 걸고 진행. 범위 크면 사용자에게 별도 시간 산정 필요함을 알릴 것 |

## 접근 원칙

무결성 검증은 대개 서명/해시 비교 로직 하나로 귀결됨 — grep으로 나온 비교 함수의 리턴값을 조작하는 게 기본. 다만 국내 금융/공공 앱에 흔한 상용 앱쉴드가 걸린 경우 난이도가 크게 올라가므로, 이 경우는 시간 산정을 미리 사용자와 협의하고 무리하게 루프를 반복하지 말 것 (실패 원인이 "스크립트 문제"가 아니라 "상용 솔루션의 구조적 방어"인 경우를 구분해야 함).
